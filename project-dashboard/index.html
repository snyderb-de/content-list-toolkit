Content List Toolkit

Cross-platform desktop tool for recursive content scanning, CSV export, email-file copy, and hash verification. Built for archival migration workflows on macOS, Linux, and Windows. Go + Wails GUI plus a parallel Python deployment for managed Windows fleets.

Open Decisions

5 items
Check Location(TGN) and Type as well as Tags?
Both are controlled fields the app ignores today. TGN is the same Getty endpoint with a different scheme; Type is the 12-value DCMI Type Vocabulary and needs no network. Cheap to add — the open question is whether either is actually going wrong, since the tag check exists because tags were breaking uploads by hand.
Clean every free-text field, or only Tags?
The same pasted invisible characters reach Title and Description of Item(s), and break a tab-delimited upload the same way. Widening the cleaning is small; a whole-row findings view is a different screen. Worth doing if an upload has ever failed on a field other than Tags.
Project license?
Default: undecided. Candidates: MIT, Apache-2.0, GPL-3.0. Pick before public release.
Final public GitHub URL?
Currently snyderb-de/content-list-toolkit. Placeholder URLs in code have been replaced with the real repo URL; still confirm the final public URL before v1.0.
Repo ownership transfer?
Default: keep with snyderb-de. Possible handoff to dpa-snyder — confirm before v1.0.
Distribution: portable-only or installers?
Default: portable-only through v1.0. Installers (MSI / DMG / AppImage) stretch goal.
Windows code-signing cert: EV or standard?
Default: standard cert (cheaper, reputation builds). EV (~$300/yr) instantly trusted but requires hardware token.
