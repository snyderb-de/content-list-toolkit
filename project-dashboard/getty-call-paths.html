Getty Call Paths

Every outbound request the Getty Tag check makes, which host serves it, and what happens when a firewall blocks it. Written for whoever approves the exception.

What to allow

Two hosts, and they are independent. Verifying terms live needs the first; downloading a term list for offline use needs the second. Allowing either one makes the feature work — they are alternative routes to the same answer, which is why both exist.

Host Port Purpose Needed for
vocab.getty.edu 443 · TLS SPARQL queries against the Art & Architecture Thesaurus Live check
aatdownloads.getty.edu 80 · plaintext Bulk vocabulary archive download Offline list
fonts.googleapis.com — Not used. The application ships its own fonts. Not required

The call paths

Request by request

Reachability probe

vocab.getty.edu

Fetches one fixed, well-known concept to decide whether the service is usable from this machine, so the answer is shown before a check runs rather than discovered afterwards. Deliberately not a search — a probe should not depend on query syntax staying still.

GET https://vocab.getty.edu/aat/300046300.json
FrequencyOnce per screen visit
Timeout6 seconds
Response~2 KB JSON

Term lookup

vocab.getty.edu

Asks whether one tag exists in the thesaurus. The tag text travels in the query string; nothing else from the spreadsheet is sent. Answered from the cache when the same tag has already been asked about during the run.

GET https://vocab.getty.edu/sparql.json?query=<SPARQL>
FrequencyOnce per distinct tag
Timeout15 seconds
ResponseUnder 1 MB, capped

Archive download

aatdownloads.getty.edu

Runs only when somebody presses Download list from Getty. Reads the index page to find the current archive, then fetches it and extracts an English term list to a file chosen by the user. Nothing is sent but the requests themselves.

GET http://aatdownloads.getty.edu/
GET http://aatdownloads.getty.edu/VocabData/aat_rel_<mmyy>.zip
FrequencyManual only
Timeout10 minutes
Download~73 MB

What leaves the machine

Only the tag text itself — controlled-vocabulary terms such as aerial photographs — and only when the live check is selected. The requests carry no collection metadata, no titles, no file names, no identifiers, and no credentials. Getty requires no account and the application holds none.

  • Not sent: the spreadsheet, any column other than Tags, file paths, machine or user names.
  • Not stored by us: responses live in memory for the duration of one check and are discarded when it ends.
  • Written to disk only on request: the downloaded term list, to a folder the user picks.

If it is blocked

Blocking is handled as a known state, not an error. A failed lookup is recorded as “could not be checked” and never as “this term is wrong” — a false accusation would send a cataloguer to re-verify metadata that was already correct.

  • Live check blocked: the indicator turns red before the run and names the cause — blocked host, DNS failure, or TLS interception. Cleaning, structural checks, and the offline list all continue to work.
  • Download blocked: the live check is unaffected. The two routes fail independently.
  • Both blocked: everything except term verification still runs, which is the half that catches the characters that break a CONTENTdm upload.

Two things worth raising in review

The download host refuses HTTPS. aatdownloads.getty.edu answers on port 80 and does not serve TLS, so that transfer is unprotected in transit. For a public vocabulary the exposure is modest, but it is real and cannot be fixed from this end.

The archives are frozen. Getty stopped refreshing these datasets after January 2026, so a downloaded list is a dated snapshot and grows staler over time. The publication date is written into the filename for that reason. The live endpoint is the only current source.
