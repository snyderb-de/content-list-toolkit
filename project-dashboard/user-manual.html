User Manual

Content List Toolkit

Scan large folder trees, write CSV inventories with optional hash columns, copy email files into curated destinations, and verify drive clones. macOS, Linux, and Windows.

Overview

What this app does

Content List Toolkit is a desktop tool for archival migration workflows. Point it at a folder, and it produces a CSV inventory of every file under that folder — relative path, size, modified date, and an optional hash. Output streams to disk so multi-million-row scans do not run out of memory.

Three additional workflows live alongside the scan: copy every email-related file under a tree into a curated destination, compare two drives' content lists to verify a clone, and check the Getty tags on a CONTENTdm export before it is uploaded.

Getting Started

The window at a glance

The GUI is organized as a vertical sidebar plus a workspace pane that swaps based on which workflow you pick.

  1. Sidebar. Three workflow tabs — Content List, Email Copy, Clone Compare — plus theme toggle.
  2. Source folder. Browse button. The folder you point this at is scanned recursively.
  3. Output folder + filename. Where the CSV (or copy destination) lands. Defaults to the source.
  4. Settings panel. Hash algorithm, exclusions, XLSX option, folders-only toggle.
  5. Generate. Starts the work. Progress bar + live stats appear.
  6. Done summary. Top extensions by count and by size, filtered samples, output paths.
The theme toggle (sun / moon) at the bottom of the sidebar saves your preference between launches.

Workflow 1

Generate a content list

Produces a recursive CSV inventory of every file under a folder.

  1. Pick a source folder. Browse to the drive or folder you want inventoried. Network drives work too, but expect slower throughput.
  2. Pick an output folder. Defaults to the source. Choose somewhere with enough free space — a CSV of 1M rows is roughly 200 MB.
  3. Tune settings. See the Settings reference below — hash algorithm, exclusions, XLSX, etc.
  4. Click Generate. The app first counts everything (so progress + ETA are real), then streams the scan to CSV.
  5. Review the done summary. Top extensions, totals, sample of filtered rows.
Memory: the scan never buffers the full row set in RAM. A 5M-row inventory uses about the same memory as a 50-row one.

Workflow 2

Copy email files

Finds every email file under a source folder and copies them into a destination, preserving the relative folder structure. Writes a manifest CSV of what got copied.

  1. Pick the email-copy tab in the sidebar.
  2. Source folder — the tree to search for email files.
  3. Destination folder — where copies land. Folder structure under the source is mirrored.
  4. Click Copy. The app walks the tree, copies files with matching extensions, and writes a manifest CSV.
  5. Review the manifest. The destination contains email-copy-manifest-{timestamp}.csv with one row per copied file: Source Path, Destination Path, Relative Path, File Name, Extension, Size in Bytes.
Re-runs overwrite: every matched file is copied unconditionally; existing files at the destination are replaced. If you need delta-only behavior, copy to an empty destination each run.

Workflow 3

Clone compare

Compares two drive content-list CSVs to verify a clone. Picks one of several verdicts and writes a diff CSV showing every difference.

  1. Generate a content list for the original drive (use BLAKE3 or SHA-256 for confidence).
  2. Generate a content list for the cloned drive — same hash algorithm.
  3. Open the clone-compare tab, point it at both CSVs.
  4. Optional: enable soft compare — accepts renamed paths with identical hashes as matches.
  5. Click Compare. Get a verdict + diff CSV.

Soft compare (PDFs)

Off by default. When enabled and a PDF's hashes differ at the byte level, the comparator re-reads the last 2 KB of each PDF, masks the PDF /ID trailer (the random pair PDF writers stamp on every save), and accepts the pair as a soft match if the masked tails are identical. Use this when a tool re-saved every PDF without changing rendered content — the verdict becomes Metadata Clone instead of Not a Clone.

Soft compare only runs on .pdf files. Other file types fall through to strict hash equality.

Workflow 4

Getty tag check

Checks the Tags column of a CONTENTdm export before you upload it. It does two jobs: it removes the invisible characters that stop a tab-delimited file loading, and it checks every term against the Getty Art & Architecture Thesaurus. It writes a corrected copy and a report, and never changes the file you point it at.

  1. Export the Access Main table to Excel, as the CONTENTdm process already has you do.
  2. Open Getty Tags and browse to the export. .xlsx, .csv, and tab-delimited .txt all work — including the .txt you are about to upload.
  3. Choose where terms are verified. See the table below.
  4. Click Check Tags. Rows with nothing wrong are not listed; a clean sheet says so.
  5. Fix what it found. Edit a tag directly, or click a suggested replacement.
  6. Apply Fixes & Re-check. Repeat until nothing is left, then upload the cleaned copy.

What it writes

Both files land beside the export. The export itself is never modified — it is the record of what Access held.

<name>-tags-cleaned.xlsxA copy with the Tags column corrected. Every other column is untouched.
<name>-tags-report.txtWhat was found, what was changed, and what still needs a person.

Use Show in Folder to find them. A sheet with nothing to correct gets no cleaned copy — an identical file would only raise the question of which one to upload.

Where terms are verified

Three choices, and they are not equivalent. Pick the first one your network allows.

OptionNeedsUse when
Getty, livevocab.getty.edu on port 443Always, when it is reachable. It is the only current source.
Built-in listNothingOffline, or the live check is blocked. 169,307 English terms ship inside the app.
A term list on this machineA file you supplyYou keep your own curated list, or you downloaded a newer one.
Do not verify termsNothingYou only want the invisible characters cleaned.
The offline lists are dated. Getty froze the downloadable archives in January 2026 but keeps revising the thesaurus, so a list can accept a term Getty has since renamed. A real example: the January archive lists landscapes as a valid term; Getty no longer holds it, having split it into qualified forms. The app says so wherever an answer comes from a dated list. The live check is the authority.

Getting a fresher list

Download list from Getty fetches Getty's current archive and extracts an English term list, saving it where you choose and selecting it. It downloads from aatdownloads.getty.edu, which is a different machine from the one the live check uses — so on some networks this works when the live check does not. The download is about 73 MB and the publication date is written into the filename.

Understanding the output

Content list CSV columns

ColumnContents
File NameFilename only, including extension.
ExtensionLowercased extension with the leading dot (e.g. .pdf).
Size in BytesRaw file size.
Size in Human ReadablePretty-printed size (e.g. 1.4 MB).
Path From Root FolderRelative path from the source root, including the filename.
Hash AlgorithmAlgorithm name (sha1, sha256, blake3) or empty when hashing is off.
Hash ValueHex digest. Empty when hashing is off.
Date CreatedFilesystem creation or birth time in local scan-machine time (YYYY-MM-DD HH:MM:SS ±HH:MM). Shows unknown when the operating system or filesystem does not expose it.
Date ModifiedFilesystem last-modified time in local scan-machine time (YYYY-MM-DD HH:MM:SS ±HH:MM). Shows unknown when unavailable.

Creation-date note: copying, restoring, downloading, or migrating a file can change its filesystem creation time. It is metadata observed during the scan, not proof of when the document contents were authored.

Folders-only mode writes a single column: Path From Root Folder.

Companion files

Every scan also writes a -report.txt alongside the CSV. It contains totals, filtered samples, top extensions, and the settings used.

my-folder-content-list-2026-05-20T13-45-02.csv
my-folder-content-list-2026-05-20T13-45-02-report.txt
my-folder-content-list-2026-05-20T13-45-02.xlsx   (if XLSX enabled)

Default base name is {source-folder}-content-list-{YYYY-MM-DDTHH-MM-SS}.csv. In folders-only mode it becomes …-folder-list-….

Hash algorithms

Hashing reads every byte of every file. Choose based on speed vs. cryptographic strength.

ModeThroughputUse for
Off~ disk read speedQuick inventories where bytewise identity does not matter.
SHA-1fastLegacy compatibility, casual fingerprinting.
SHA-256slower, strongerDefault for verifications that must hold up to scrutiny.
BLAKE3fastest secure hashBest speed/strength trade-off. Built in — nothing to install.
Clone verification: use BLAKE3 or SHA-256. SHA-1 is fine for sanity checks but collisions are demonstrable, so avoid it for adversarial scenarios.

CSV chunking for huge scans

CSV files over a few hundred thousand rows get unwieldy in Excel and many text editors. Content List Toolkit splits output every 300,000 rows by default.

Row countOutput files
1 – 300,000{name}.csv
300,001 – 600,000{name}-001.csv, {name}-002.csv
900,001+{name}-001.csv, {name}-002.csv, {name}-003.csv, …

XLSX files are split using the same rule. Each chunk includes its own header row.

Filters & exclusions

Always-excluded files

These never appear in output regardless of settings:

PatternWhy
pagefile.sys, hiberfil.sys, swapfile.sysWindows swap files; not user content.
Thumbs.db, ehthumbs.db, desktop.iniWindows OS noise.
.DS_StoremacOS Finder metadata.
~$*, .~lock.*Office/LibreOffice lock files.
._*macOS resource forks on non-HFS filesystems.
*.tmpTemporary files.

Always-excluded directories

Recycle bins, indexer caches, and other OS infrastructure folders.

  • $RECYCLE.BIN, System Volume Information
  • .Spotlight-V100, .Trashes, .fseventsd
  • .TemporaryItems, .DocumentRevisions-V100

User-toggleable filters

  • Hidden files — names starting with . or with the hidden attribute set.
  • System files — short list of OS metadata files.
  • Extension list — comma-separated. Match is on the lowercased extension without the dot.

Clone-compare verdicts

Compare results land on one of these verdicts. The diff CSV always lists every actual difference, regardless of verdict.

VerdictMeaning
Exact CloneEvery file's path, size, and hash agree across both drives. The clone is byte-identical at the file level.
Content CloneEvery hash matches, but paths or extra metadata differ. The data is intact; the layout was reorganized.
Metadata CloneSoft-compare only. Some PDF hashes differ at the byte level but their normalized content matches — i.e. only the PDF /ID metadata changed. Treated as a content-equivalent clone.
Not a CloneAt least one file is missing or has a true hash mismatch. Diff CSV lists every divergence.
Tip: if you got a verdict you didn't expect, sort the diff CSV by the Difference Type column to see what changed.

Getty findings, and what to do about each

Every finding leads with what it wants from you.

PrefixMeaning
FixedAlready corrected in the cleaned copy. Nothing to do.
Must FixCorrect it before uploading.
ReviewA judgement call. It will upload either way.

What it looks for

FindingWhat it means
Invisible charactersA no-break space, zero-width space, tab, or similar, pasted in along with the term. These are what stop a tab-delimited upload. Fixed automatically.
SeparatorA semicolon without its following space, or a space before it. Fixed automatically.
SpacingLeading, trailing, or repeated spaces. Fixed automatically.
Empty tagTwo semicolons together, or a trailing one. The empty entry is dropped.
Not in AATGetty has no such term. Suggested replacements appear beside it where there are any.
Spelling caseThe term exists but Getty spells it differently. AAT treats case as meaningful — acacia the wood is not Acacia the genus.
Unclosed bracketA qualified term that lost its closing bracket, such as counters (furniture. No vocabulary will ever match it.
DuplicateThe same term twice in one cell, ignoring case.
Tag countFewer than 3 or more than 5 terms.
Too longThe cell is at or over 255 characters, the width of the Access Tags field. Access truncates at entry by character count rather than at a separator, so the last term arrives cut mid-word while looking complete.
Damaged textA replacement character from an earlier encoding error. The original character cannot be recovered, so it is reported rather than guessed at.
Not checkedThe vocabulary could not be reached for that term. This is not the same as the term being wrong, and is never reported as though it were.

If Getty cannot be reached

The indicator beside the live option turns red before you run anything, and names the cause — a blocked host, a DNS failure, or a proxy intercepting the connection. Cleaning and every structural check still work; only term verification stops. Terms are then reported as not checked, never as wrong, because sending someone to re-verify metadata that was correct is worse than saying nothing.

Switch to the built-in list and the check runs with no network at all.

If something goes wrong

macOS: "could not verify free of malware"

Gatekeeper blocking an unsigned binary. Right-click the app → Open → Open. Or System Settings → Privacy & Security → "Open Anyway." Or terminal: xattr -d com.apple.quarantine /path/to/app.

Windows: SmartScreen prompt on launch

Click "More info" → "Run anyway." Will go away once the binary is code-signed.

Windows: .exe does not launch at all

Fixed in v0.2.2. If you are on an earlier version, upgrade to the current .exe. Details in docs/debug/windows-launch-failure.md in the repo.

Output folder is not writable

The app verifies the folder is writable before scanning. If it errors out, pick a different output location.

The CSV exists already

You will be prompted to overwrite. Pick yes to replace it, or no to go back and rename the output file.

Scan is slower than expected

Network drives, encrypted volumes, and large hash modes (SHA-256, BLAKE3) all slow throughput. For a quick inventory, turn hashing off and rerun.

Frequently asked questions

Which download do I need?

macOS: the .app. Linux: the binary. Windows: the .exe. There is one application now — the Python runtime was retired once the Windows .exe could do everything it did. The .exe needs no admin rights and no installer, and runs from a USB drive or network share, so it suits managed fleets as well as personal machines.

Does it work on network drives?

Yes. SMB / NFS / mapped drives all scan correctly. Throughput is limited by network round-trip time per file, so a network scan is typically 5–20× slower than a local scan. Run with hashing off first to validate the inventory, then re-run with BLAKE3 if you need verification.

How large a scan can it handle?

There is no fixed cap. CSVs auto-chunk every 300,000 rows, and the scan streams to disk so memory stays flat regardless of row count. Multi-million-row scans are routine. The dominant cost is hash mode (full byte read of every file) and disk throughput.

Why are $RECYCLE.BIN / System Volume Information not in the output?

These OS infrastructure folders are always excluded, with no user toggle, because they never contain archival content. The same applies to swap files (pagefile.sys, hiberfil.sys, swapfile.sys), macOS metadata (.Spotlight-V100, .Trashes, .fseventsd), Office lock files (~$*, .~lock.*), and resource forks (._*).

Can I resume an interrupted scan?

No — stopping a scan discards its partial CSV. Scans are fast enough that restart is the safer model. For very large drives, work folder-by-folder so a stop only loses one subtree.

Do any of the hash options need something installed?

No. BLAKE3, SHA-1, and SHA-256 are all built into the application via github.com/zeebo/blake3 and the Go standard library. This used to be a real question on the retired Python runtime, where BLAKE3 needed a separate package.

Will email-copy modify or open .pst / .ost files?

No. Email-copy is a pure file copy by extension — it never opens, parses, or mutates email containers. Outlook can keep .pst / .ost exclusively locked while open; close Outlook before copying or expect "file in use" errors.

What if soft compare returns Metadata Clone but I want to know which PDFs differed?

The diff CSV always lists every divergence, regardless of verdict. Look for rows where Difference Type indicates a hash mismatch — those are the PDFs that matched only after /ID normalization.

Why is the XLSX file split into multiple files?

Excel's .xlsx format caps at 1,048,576 rows per sheet, and Excel itself becomes sluggish well below that. Splitting at 300,000 rows keeps each file responsive and aligns with the matching CSV chunks for easy cross-referencing.

How do I reset all settings?

Close the app, delete the settings file at the path listed in About for your OS, relaunch. The app re-creates it with defaults on next save.

Tips

  • Start with hashing Off to validate paths and counts, then re-run with BLAKE3 once you trust the inventory plan.
  • Stop a scan with s or esc in the TUI; in the GUI use the Stop button.
  • Filtered samples in the done summary tell you what got skipped. Glance over them to confirm exclusions did what you expected.
  • For migrations, write the original and clone CSVs to the same output folder so the diff is easy to file alongside.
  • The Windows .exe needs no admin rights and no installer — it runs from wherever you put it. Recommend it to less-technical users.
  • Folders-only mode + a depth cap is the fastest way to map a drive before deciding what to scan in full.
  • Settings persist across launches per-user. Reset them by deleting the settings file (path listed in About).
